# Use Intermediate Variables

Enhance code clarity by storing results of sub-expressions in intermediate variables.

This code example shows how using intermediate variables can improve readability and maintainability:

## Good code

```rust
// Good example: Using intermediate variables
fn process_data(data: Vec<i32>) -> (i32, i32, f64) {
    let sum: i32 = data.iter().sum();
    let count = data.len() as i32;
    // Store intermediate results in named variables
    let average = if count > 0 { sum as f64 / count as f64 } else { 0.0 };
    let max_value = *data.iter().max().unwrap_or(&0);
    (sum, max_value, average)
}
```

## Bad code

```rust
// Bad example: Not using intermediate variables
fn process_data(data: Vec<i32>) -> (i32, i32, f64) {
    (
        data.iter().sum(),
        *data.iter().max().unwrap_or(&0),

if data.len() > 0 { data.iter().sum::<i32>() as f64 / data.len() as f64 } else { 0.0 }
    )
}
```

The good example uses intermediate variables to store the results of sub-expressions. This approach makes the code more readable and self-documenting. Each variable has a clear purpose, and the logic is easier to follow.

## Memo

Using intermediate variables can sometimes help the compiler optimize the code better, as it provides clearer hints about the programmer's intentions.
