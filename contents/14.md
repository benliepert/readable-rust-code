# Ensure function names clearly describe their actions or results

Function names should be descriptive and indicate what the function does or what result it produces.

Clear and descriptive function names help other developers understand the purpose and behavior of the function without needing to read its implementation. This practice enhances code readability and maintainability.

## Good code

```rust
// Good example: Descriptive function names
fn calculate_area(radius: f64) -> f64 {
    // Calculate the area of a circle
    3.14159 * radius * radius
}

fn print_greeting(name: &str) {
    // Print a greeting message
    println!("Hello, {}!", name);
}

let area = calculate_area(5.0);
print_greeting("Alice");
```

## Bad code

```rust
// Bad example: Vague function names
fn calc(r: f64) -> f64 {
    // Calculate the area of a circle
    3.14159 * r * r
}

fn pg(n: &str) {
    // Print a greeting message
    println!("Hello, {}!", n);
}

let a = calc(5.0);
pg("Alice");
```

In the good example, the function names calculate_area and print_greeting clearly describe their actions, making the code easy to understand. In the bad example, the vague names calc and pg do not provide enough information about what the functions do, making the code harder to read and understand.

## Memo

In Rust, function names are typically written in snake_case, which means words are separated by underscores. This convention helps improve readability and consistency in the codebase.
